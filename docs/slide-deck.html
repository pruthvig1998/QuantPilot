The problem Required point 1 of 8 - problem and users

Retail options research is a black box that sells confidence

  • Buyers of weekly options mostly lose: premium decays daily, IV crushes after events, and most "picks" never show breakeven, probability, or risk.
  • The evidence lives in fragmented places - options chains, order flow, chart structure, sector breadth, event calendars, earnings dates - and no retail tool assembles it into one auditable argument.
  • LLM chatbots make it worse: fluent recommendations with no citations, no unknowns, and no record of what they got wrong.

The solution Required point 2 of 8 - solution

An investigating agent, not a chatbot

  • Each morning it builds an evidence packet per name - board score, order blocks, guardrail checks, event risk, earnings dates. Missing data is null, and named.
  • A bull and a bear argue the packet; a judge verdicts TRADE WATCH SKIP with conviction - and can send the debate back once when the evidence has a named gap.
  • Output is a trade card: levels, a chosen contract, sizing at 1% risk, plain-English Greeks, and every check listed as passed, failed, or unknown - plus a journal that scores the agent's own calls.
Investigate Argue Confess If a value is missing, it prints as unknown If a check fails, it prints on the card
Speaker note

Three verbs define the product: investigate, argue, confess. If a value is missing, it is printed as unknown. If a check fails, it is printed on the card. The agent's honesty is mechanical, not prompt-deep.

Technical stack Required point 4 of 8 - technical stack

What it is built on

  • Python 3.12; requests / pandas / numpy; SQLite; pytest (263 tests).
  • Data: Yahoo Finance public APIs (chart + options) behind a provider interface - the harness and the direct route are interchangeable.
  • Brain: NVIDIA Nemotron (nvidia/nemotron-3-ultra-550b-a55b) over an OpenAI-compatible endpoint; all calls flow through one provider layer.
  • Delivery: static dashboard HTML (zero external assets), plain-text and Markdown briefings, a CLI morning runner with a deterministic SAMPLE_MODE replay for judges.
No framework magic: the repo is small enough for a judge to read SAMPLE_MODE: full pipeline, no keys, no network

No framework magic to hide behind - the repo is small enough for a judge to read, and SAMPLE_MODE lets them re-run the whole pipeline with no keys and no network.

Sponsor tech - Zetaris Required point 5 of 8 - Zetaris and Meterless

Zetaris - one harness over fragmented market data

  • A local Zetaris platform holds Yahoo's chart API as 46 REST tables: daily bars (2y) for 12 watchlist names + 10 sector ETFs, weekly (5y) and 5-minute (5d) bars for the watchlist, flattened into SQL views.
  • The agent queries a single SQL interface (ZetarisProvider); swapping to direct Yahoo is one config value with zero downstream changes.
  • This is the Track 02 "fragmented sources" story made literal: one question, many sources, one harness.

Sponsor tech - Meterless + NVIDIA Required point 5 of 8 - Zetaris and Meterless

Meterless engines and runtime, Nemotron brain

  • Build rule: the official Meterless H-Mem engine, vendored unmodified (Apache-2.0), driven via a Node bridge - the agent's superseding long-term memory (remember / recall / count). It does real work: past calls are recalled into the next run's packets.
  • Power rule: a Meterless Runtime provider connection implemented in the product to the published Runtime 1.4 contract (connect-link token parsing, provider headers, /v1/models probe), per the Meterless team's Oct 19 HackOS ruling, confirmed directly to this project on Oct 23. On Oct 26 the full live run went through Nightshift 0.92.7 (9 of 9 calls, model logged per call) - the strict Rule 15.2 reading is met, not just the ruling.
  • Brain: Nemotron ultra-550b. The planned super-120b endpoint has returned 404 on NVIDIA's side since Oct 20 (verified on multiple keys); the model is one env line and flips back if it returns.
